Documentation

Scalability

In Rahti it is easy to deploy more replicas with a click of a button.

The frontend accesses the backend through a cluster IP that represents multiple pods/devices with a single IP. Kubernetes takes this one step further providing load balacing in the internal network.

Scaling the backend allows for more through put of requests to a certain point in which the database might not be able to handle the queries but with such a simple demo it is almost impossible for the database to be overwelmed.

Persistence

I terminated the pod, and after creating a new pod the data was still the same.

There is a persistent volume which stores the database's data outside the containers.

The database deployment is bound to this volume which saves the changes made in the MySQL.

Pod recovery

Terminating a backend pod manually automatically start a new backend pod.

It is Kubernetes continuously compares your current running pods with your target configuration. Not Rahti.

ConfigMap vs. Secrets

ConfigMaps are for non-sensitive configuration data like environmental variables, config files, and URLs. Stores as plaintext.

While Secrets are for confidental secure configuration data like passwords, private keys, and TLS certificates. Stores as base64 encoded string.
